# Captures from before the evening of 2026-09-08

Archived when the firmware moved to v4. They are still valid as data, but
**their `go` marker is not**: up to v3 it was a human keypress, so ±100 ms. On
`accel_20260907_160108.csv` it lands ~90 ms *after* the movement it is supposed
to mark.

Use them to validate the *mechanism* (rate, integrity, sample-level placement).
**Do not use them to tune the detector's thresholds**: tuning a ±10 ms threshold
against a ±100 ms reference is circular. That needs v4 captures, where `go` is
generated by the firmware itself.

Other differences from the v4 format:

- no pre-roll: recording started exactly at `set`, so the detector is blind for
  the first ~800 ms (the LTA's convergence time) — precisely inside the window
  where a false start counts
- rate ~977 Hz (v2, free-running) or ~863 Hz (v3); the detector derives it from
  the timestamps, so they still open
- the markers are at the end of the file, not at the top
- an extra `host_iso` column, ignored

`blockstart_20260831_test0.csv` and the two `kinestart_imu_*` are older still
and use different column formats.
